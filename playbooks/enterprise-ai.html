O contexto

Por que o time
precisa de IA agora.

Velocidade, escala e consistência. Os três vetores que mudam quando IA entra no fluxo de trabalho do time.

Velocidade

Tarefas que levavam horas — análise, redação, pesquisa, código — entregues em minutos com o contexto certo.

Escala

Um único operador conduz múltiplos agentes IA em paralelo, amplificando a capacidade do time sem aumentar o headcount.

Consistência

Com o contexto certo — Projects, Skills, Specs — o output é consistente. A qualidade não depende do humor ou da memória de ninguém.

Como Conversar com IA
  • Dê um papel: "Você é especialista em hospitalidade de luxo..." — contexto muda tudo.
  • Seja específico: "Escreva um email de 3 parágrafos, tom profissional mas caloroso, para o cliente que pediu prazo estendido."
  • Dê exemplos (few-shot): "Aqui está um email no tom que queremos: [exemplo]. Agora escreva um similar sobre..."
  • Itere: Nunca aceite o primeiro resultado sem ajustes. Peça: "Torne mais conciso", "Adicione urgência", "Reformule o 2º parágrafo."
  • Use Artifacts: Para tabelas, documentos e código — peça output estruturado, não paredes de texto.
Método RPI: Research → Plan → Implement. Nunca pule direto para a execução.
Como Extrair o Máximo
  • Método RPI: Research (explore com IA livre) → Plan (estruture o que aprendeu) → Implement (execute com contexto limpo).
  • Use Research Mode do Claude para tarefas que precisam de fontes externas verificadas.
  • NotebookLM para base de conhecimento interna. Coloque manuais, processos e PDFs — a IA responde com base nos seus documentos.
  • Crie Skills reutilizáveis. Tarefas recorrentes viram instruções salvas: email de follow-up, proposta, análise de métricas.
  • Valide sempre: IA pode alucinar. Use como acelerador inteligente, não como fonte final de verdade.
NotebookLM com os documentos da empresa = IA que fala a linguagem da empresa, não do mundo genérico.
Economia de Tokens
  • Use Projects com instruções fixas. Configurado uma vez, você não repete o contexto em cada conversa.
  • Resuma conversas longas. Antes de continuar: "Resuma em 5 pontos o que decidimos até agora" → nova conversa.
  • Modelos certos para as tarefas certas. Haiku para triagem e rascunhos; Sonnet para trabalho complexo; Opus para decisões estratégicas.
  • Não carregue arquivos desnecessários. O contexto é finito — só inclua o que é realmente relevante.
  • Regra dos 40%: Máximo 40% do contexto deve ser histórico. 60% deve ser instrução estruturada.
Projects + Regra dos 40% = contexto sempre fresco. Qualidade consistente sem desperdício.
Segurança e Privacidade
  • Nunca coloque senhas, tokens ou chaves de API em prompts. Use variáveis de ambiente — nunca texto direto.
  • Não use conta Free com dados confidenciais da empresa. No plano Free, o histórico pode ser usado para treinar modelos.
  • Use Projects para isolar contextos. Dados de um cliente não devem cruzar para o projeto de outro.
  • Revise antes de enviar para clientes. A IA não conhece seus relacionamentos — valide o tom e os fatos.
  • Dados pessoais de terceiros? Não coloque no prompt. CPFs, cartões, dados médicos — nunca.
Regra de ouro: se você não colocaria essa informação num email corporativo sem criptografia, não coloque na IA.
